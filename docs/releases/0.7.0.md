# Jev Java 0.7.0

Synchronizes provider contracts and interfaces against upstream specifications
checked on 2026-11-28, and includes the OpenAI generic Score label preservation
fix from `main`. Java 17 remains the minimum runtime and existing provider
default models stay unchanged.

## Upstream contract and interface updates

- **TypeSafe model listing and long context (`jev-typesafe`):**
  - `TypeSafeJevClient.listModels()` / `listModelsAsync()` query
    `GET /v1/models` and return immutable `TypeSafeModelList` / `TypeSafeModel`
    records with defensive raw JSON preservation. Supports `baseUrl` derivation
    and explicit `.modelsEndpoint(URI)` overrides.
  - Opt into `TypeSafe-Danger-Zone-Long-Context: true` (262k context limits)
    via `TypeSafeJevClient.builder().longContext(true)`, Spring property
    `jev.long-context=true`, or per-request `TypeSafeRequestOptions`
    (which also supports per-request `.model(...)` overrides) across manual and
    annotated record APIs.
- **Transport GET support (`jev-core`, `jev-spring-webflux`):**
  - `JevTransport` gains a backwards-compatible default `get(URI, Map)` method.
  - `HttpTransport` and `WebClientJevTransport` implement `get` without a
    `Content-Type` header or body while preserving deadline, retry, cancellation,
    and sanitized error contracts.
- **Optional question instructions and one-sided Noul criteria (`jev-core`):**
  - `ChoiceQuestion.of(id, ...)`, `ScoreQuestion.of(id, levels)`, and
    `NoulQuestion.ofCriteria(id, yes, no)` permit omitting `instructions` when
    criteria define the judgment on TypeSafe, OpenRouter, Cloudflare, and
    Vercel `DECISION_V4`.
  - One-sided `Noul` criteria omit null sides cleanly; OpenAI and legacy
    Vercel `EVALUATION_V4` continue rejecting omitted instructions before HTTP.
- **OpenRouter Decisions alignment (`jev-openrouter`):**
  - Accepts optional instructions and one-sided Noul criteria matching
    `OpenRouterTeam/ai-sdk-provider` commit `9f6ca11`.
  - Any `refusal` answer in an OpenRouter response now fails the evaluation
    with `JevException.Kind.REFUSAL` before decoding sibling answers.
- **Vercel decision-model v4 options (`jev-vercel`, `jev-spring-boot-autoconfigure`):**
  - `VercelJevClient.Builder` adds `.maxOutputTokens(int)` and
    `.reasoning(VercelJevClient.Reasoning)` for `Protocol.DECISION_V4` (and
    Spring properties `jev.vercel-max-output-tokens` / `jev.vercel-reasoning`).
  - Both options reject legacy `EVALUATION_V4` before HTTP.
- **OpenAI generic Score labels (`jev-core`):**
  - Preserves empty, whitespace-only, and repeated Score labels by zero-based
    index in generic `evaluate` calls, matching the native `decide` contract.

## Compatibility

Existing `JevTransport` implementations that only override `post` and `close`
remain source- and binary-compatible via the default `get` method (returning a
failed future with `JevException.Kind.VALIDATION`). `Question.instructions()` now
returns `null` when a question is created with one of the new criteria-only
factories; existing `instructions`-accepting factories keep rejecting null or
blank values. `AbstractJevClient` updates `User-Agent` to `jev-java/0.7.0`.
